# Connecting VS Code to GeoLab — Video Script

**Runtime:** ~6:50 (6–7 min target)
**Format:** Screen-capture (browser JupyterLab + local VS Code) + narration, light motion graphics for titles/lower-thirds/code call-outs
**Audience:** Researchers and educators already comfortable in GeoLab who want to keep working in VS Code — debugging, git, multi-file editing — while code still runs on GeoLab's compute
**Source:** [docs.earthscope.org/geolab/advanced-topics/connect-vscode-to-geolab](https://docs.earthscope.org/geolab/advanced-topics/connect-vscode-to-geolab)

### Production notes
- Never show a real, still-valid token on screen — generate a throwaway session for recording and let it expire (or manually invalidate it) immediately after capture; the token string is highlighted deliberately in this script, so blur or fake it in post if the real one was ever visible during recording.
- Record the "server culled" scenario for real if possible (let a demo session idle out before recording that beat) rather than describing it only in voice-over — seeing the actual stale-token error once builds more confidence than a warning card alone.
- Confirm the exact VS Code menu wording ("Enter the URL of the running JupyterHub Server…") and extension names against the current VS Code Marketplace listings before final recording, since extension UI text can change independently of the GeoLab docs.
- Verify the Python snippet and hub-token fallback URL against the live docs page before recording: https://docs.earthscope.org/geolab/advanced-topics/connect-vscode-to-geolab
