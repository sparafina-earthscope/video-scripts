# Pushing GeoLab Images to GHCR and ECR — Video Script

**Runtime:** ~6:55 (6–7 min target)
**Format:** Screen-capture (terminal + GitHub + AWS console) + narration, light motion graphics for titles/lower-thirds/code call-outs
**Audience:** Researchers and teams who've already built a custom GeoLab image and need private hosting, access control, or CI-driven builds beyond what Docker Hub offers
**Source:** [docs.earthscope.org/geolab/advanced-topics/environments/pushing-to-ghcr-ecr](https://docs.earthscope.org/geolab/advanced-topics/environments/pushing-to-ghcr-ecr)
**Series context:** Follows "Building Custom Images for GeoLab," which pushed to Docker Hub for simplicity and pointed here for the two other registry options

GHCR namespaces images under your GitHub user or organization; ECR namespaces under a registry alias tied to your AWS account. GHCR authentication works from anywhere; ECR's public registry only authenticates in the us-east-1 region, regardless of where you actually deploy. And GHCR tokens don't expire by default, where an ECR login token is only valid for twelve hours — you'll be re-authenticating more often." |

| 1:25–1:25 | Lower third: **"Create a token"** | **VO:** "Authentication starts with a personal access token." |
| 1:25–1:55 | Screen capture: GitHub Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token. Scope checkboxes highlighted one at a time: `write:packages`, `read:packages`, `delete:packages` (marked "optional"). | **VO:** "Under Settings, Developer settings, Personal access tokens, generate a classic token. | 2:00–2:30 | Screen capture: terminal, two blocks shown in sequence. <pre>export CR_PAT=&lt;YOUR_TOKEN&gt;<br>echo $CR_PAT \| docker login ghcr.io -u &lt;github_username&gt; --password-stdin</pre> then <pre>gh auth login<br>gh auth token \| docker login ghcr.io -u &lt;github_username&gt; --password-stdin</pre> Both end with `Login Succeeded` in green. | **VO:** "Export the token as an environment variable and pipe it into docker login — or, if you have the GitHub CLI installed, authenticate with gh auth login and pipe its token in instead. Layers upload just like they did to Docker Hub." |
| 2:55–3:00 | Lower third: **"Make it public (optional)"** | **VO:** "One important detail: GHCR images are private by default." |

| 3:25–3:50 | On-screen troubleshooting card: **"401 Unauthorized"** → "token expired, missing write:packages scope, or username doesn't match token owner" / **"403 Forbidden"** → "check scope, visibility, and namespace; GitHub Actions needs permissions: packages: write." | **VO:** "If the push fails, it's almost always one of two errors. A 401 means Docker isn't authenticated — check that your token hasn't expired and that it actually has the write colon packages scope. A 403 means you're authenticated but not allowed — double-check the scope again, the image's visibility settings, and that your namespace is spelled correctly. Pushing from GitHub Actions specifically also needs permissions colon packages colon write set in the workflow file, or the push is denied before it even starts." |

| 3:55–4:15 | Screen capture: terminal running `aws --version`, `aws configure list` showing a named profile; browser showing the ECR console with a registry alias highlighted, e.g. `a1b2c3d4`. | **VO:** "You'll need AWS CLI version 2, a configured AWS profile, and your public registry alias — find that in the ECR console; it looks like a short, random string tied to your account." |
| 4:15–4:20 | Lower third: **"Create the repository"** | **VO:** "ECR needs the repository to exist before you can push to it." |
| 4:20–4:40 | Screen capture: terminal. <pre>aws ecr-public create-repository \<br>&nbsp;&nbsp;--repository-name my-public-repo \<br>&nbsp;&nbsp;--region us-east-1</pre> | **VO:** "Create it with aws ecr-public create-repository, a name, and the region — which, for ECR's public registry, must always be us-east-1, no matter where your other AWS resources actually live." |
| 4:40–4:45 | Lower third: **"Authenticate"** | **VO:** "Login works differently here — through a short-lived token." |
| 4:45–5:10 | Screen capture: terminal. <pre>aws ecr-public get-login-password --region us-east-1 --profile &lt;user-profile&gt; \<br>&nbsp;&nbsp;\| docker login --username AWS --password-stdin public.ecr.aws</pre> On-screen badge: **"Token valid 12 hours."** | **VO:** "Get a login password from AWS, scoped to us-east-1 and your profile, and pipe it into docker login. Remember that token badge — twelve hours — because unlike GHCR, this one will expire mid-project if you're not careful, and you'll need to re-run this same command to refresh it." |
| 5:10–5:15 | Lower third: **"Tag and push"** | **VO:** "Same tag-and-push pattern, ECR's namespace." |
| 5:15–5:35 | Screen capture: terminal. <pre>docker tag my_geolab:latest \<br>&nbsp;&nbsp;public.ecr.aws/&lt;registry_alias&gt;/my_geolab:latest<br>docker push public.ecr.aws/&lt;registry_alias&gt;/my_geolab:latest</pre> | **VO:** "Tag with public.ecr.aws, your registry alias, and the image name, then push, exactly like the other two registries." |
| 5:35–6:00 | On-screen troubleshooting card: **"401 Unauthorized"** → "refresh with `aws sso login`, confirm identity with `aws sts get-caller-identity`, confirm region is us-east-1" / **"403 Forbidden"** → "IAM role needs GetAuthorizationToken, BatchCheckLayerAvailability, InitiateLayerUpload, UploadLayerPart, CompleteLayerUpload, PutImage." | **VO:** "A 401 here usually means that twelve-hour token expired — refresh your SSO session, confirm your identity with aws sts get-caller-identity, and double-check you're still targeting us-east-1. A 403 means your IAM role is missing one of the specific ECR permissions a push actually needs — the token, the layer checks, the upload steps, and the final image write. Missing any one of those, and the push is denied partway through." |

If your team already lives in GitHub, GHCR keeps image access control right next to your code and your CI. If your team already lives in AWS, ECR keeps it inside the same account and IAM policies as everything else you run." |

### Production notes
- Use disposable credentials for all screen capture: a throwaway GitHub personal access token (revoke it immediately after recording) and a non-production AWS profile/IAM role. Never let a real, still-valid token appear on screen, even briefly.
- Blur or replace the registry alias and any account IDs shown in the ECR console — these are account-identifying even on a "public" registry.
- The us-east-1 requirement (4:20–4:40) and the 12-hour ECR token lifetime (4:45–5:10) are the two details most likely to cause support questions later — consider a pinned comment or on-screen callout reinforcing both.
- Verify all commands, scopes, and IAM permission names against the live docs before final recording, since registry APIs and required scopes can change: https://docs.earthscope.org/geolab/advanced-topics/environments/pushing-to-ghcr-ecr
- This script assumes viewers already have a built local image from "Building Custom Images for GeoLab." If publishing standalone, add a ~15s recap near 0:20 of what `docker build --tag my_geolab:latest` produces.
